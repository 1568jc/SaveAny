# 开发日志：本地视频上传解析

> 本文档记录「本地视频上传解析」这次二次开发的完整过程：需求、关键决策、实现方案、测试结果与遗留问题。
>
> 目的是让后续接手的人不用翻代码就能搞清楚「为什么这么做」，尤其是那些看起来奇怪但有原因的写法。

---

## 一、需求背景

原项目只支持一种视频来源：**在线视频链接**（yt-dlp 解析 1800+ 平台）。

但用户手里的很多视频没有公开链接——本地录屏、会议录像、下载好的课程、手机拍的素材。这些视频同样需要「生成字幕 → AI 总结 → 思维导图 → 问答」的能力。

因此新增第二种视频来源：**本地上传视频**。

### 硬性约束

开发前明确的边界，全程遵守：

| 约束 | 落实情况 |
|---|---|
| 不破坏原有在线视频解析功能 | 未修改 `downloader.py`、`douyin.py`、`summarizer.py` |
| 不做大规模重构、不换技术栈 | 沿用 FastAPI + Vue 3，无架构改动 |
| 优先复用现有能力 | 总结/导图/问答/字幕导出 100% 复用，未新建任何一套 |
| 不随意修改数据库 | 表结构零改动，任务状态放内存 |
| 不修改会员、支付、用户系统 | 仅在 `api_summarize.py` 加了 3 行管理员早退（见「五、管理员账号」） |
| 不长期保存用户视频 | 转写完成即删除视频与音频，仅保留文字结果 |

### 第一版范围

**做**：MP4 等常见格式、最大 500MB、最长 60 分钟、登录才能用、明确的失败提示、处理状态展示、可删除。

**不做**：视频库、上传历史（服务端）、批量上传、视频剪辑、多用户共享、高级视频理解、复杂权限系统。

## 二、架构分析：为什么能低成本复用

动手前先摸清了现有代码的五个关键位置：

| 环节 | 位置 |
|---|---|
| 视频链接解析入口 | `main.py` 的 `/api/parse`，抖音走 `douyin.py`，其余走 `downloader.py` |
| 字幕生成 | `summarizer.py` 的 `SubtitleExtractor.extract(url)` |
| AI 总结 | `api_summarize.py` 的 `/api/summarize`（SSE 流式） |
| 思维导图 | 同一个 SSE 端点内，不是独立接口 |
| 视频问答 | `api_summarize.py` 的 `/api/chat` |
| 前端组织 | 单页 `App.vue`：`HeroSection`（输入）→ 左 `VideoResult` + 右 `VideoSummary`（4 个 Tab） |

### 关键发现：整条流水线只有一个契约

`SubtitleExtractor.extract()` 的返回结构是后续所有功能的唯一输入：

```python
{
    "has_subtitle": bool,
    "language": str,
    "subtitle_type": "manual" | "auto" | "none",
    "segments": [{"start": float, "end": float, "text": str}, ...],
    "full_text": str
}
```

**只要本地视频的语音识别结果产出同样的结构，后面的总结、导图、问答、字幕导出就能原样复用，一行都不用改。**

这是整个方案成立的基础。实现时新增了一个 `subtitle_type` 取值 `"asr"`（表示语音识别生成），前端据此显示「AI 识别字幕」。

### 第二个发现：问答接口本来就不依赖 URL

`/api/chat` 的请求体是 `{url, question, subtitle_text}`，代码里只要 `subtitle_text` 非空就完全不碰 `url`。

所以**本地视频的问答功能是零改动复用的**，后端一行没动。

## 三、技术选型：语音识别用什么

这是本次唯一无法复用现有能力的环节——DeepSeek 没有 ASR 接口，现有 API Key 用不上。

### 环境事实

- `ffmpeg` / `ffprobe` 已在 PATH（项目自带 `tools/ffmpeg/`）→ 音频提取零成本
- `torch 2.9.1+cpu` 已装，但**无 GPU**
- `python-multipart` 已装 → 文件上传无需新依赖

### 三个候选方案

| 方案 | 代价 | 速度（CPU） | 结论 |
|---|---|---|---|
| **faster-whisper** | 新增 `faster-whisper` + `ctranslate2`，首次运行下载模型 | 约 0.4x 实时 | **采用** |
| openai-whisper | 复用已装 torch，但 torch 是 CPU 版 | 比上者慢 4–8 倍 | 否决，60 分钟视频要跑 30–60 分钟 |
| 第三方 ASR API | 需要新 API Key + 按量计费 + 音频上传第三方 | 最快 | 否决，与「不长期保存用户视频」的隐私定位冲突 |

**选择 faster-whisper 的理由**：完全本地、无需 API Key、零调用费用、音频不出本机（契合隐私定位），CPU 下速度可接受。

模型大小、设备、语言均可通过环境变量调整，有 GPU 时改 `WHISPER_DEVICE=cuda` 可提速 5–10 倍。

## 四、实现方案

### 数据流

```
本地视频上传
  ↓  ffprobe 校验（真的是视频？有音轨？时长合规？）
  ↓  ffmpeg 提取音频（16kHz 单声道 WAV，Whisper 原生格式）
  ↓  faster-whisper 转写 → segments[{start, end, text}]
  ↓  ★ 与 SubtitleExtractor.extract() 完全同构 ★
  ↓
复用现有流程：AI 总结 / 思维导图 / 视频问答 / 字幕导出
```

### 新增接口

全部挂在 `/api/local/*` 独立前缀下，与原有路由零冲突：

| 接口 | 说明 |
|---|---|
| `GET /api/local/config` | 返回该用户实际生效的限额（管理员更宽松）、支持格式、ASR 是否就绪 |
| `POST /api/local/upload` | 上传视频，落盘后立即返回 `job_id`，处理在后台串行进行 |
| `GET /api/local/status/{job_id}` | 轮询处理状态与进度 |
| `DELETE /api/local/job/{job_id}` | 删除上传的视频与生成结果 |
| `POST /api/local/summarize` | AI 总结（SSE 流式） |

`POST /api/local/summarize` 发出的事件序列与 `/api/summarize` **完全一致**：

```
subtitle → summary(多次) → mindmap → quota → done
```

正因为一致，前端 `VideoSummary.vue` 的渲染、字幕导出、思维导图导出逻辑才能原样复用——只换了一个请求函数。

### 任务状态设计

**不写数据库**，任务状态放内存字典，理由：

1. 「不随意修改数据库」是硬约束
2. 第一版明确不做上传历史
3. 契合「不长期保存用户视频」——进程退出即全清

生命周期：

- 视频文件在**音频提取完成后立即删除**
- 音频文件在**转写完成后立即删除**
- 内存里只留文字结果，2 小时 TTL，另有 5 分钟一次的后台清理任务
- 进程退出时清空整个上传目录

处理用 `ThreadPoolExecutor(max_workers=1)` **串行**执行——语音识别是 CPU 密集型，并行只会互相拖慢。

### 前端组织

- `HeroSection.vue` 顶部新增来源切换：**🔗 在线链接** / **📁 本地上传**，原有 URL 表单完全不动
- 新增 `LocalUpload.vue`（拖拽上传、进度、状态、错误提示）和 `LocalVideoResult.vue`（结果卡片）
- **没有改 `VideoResult.vue`**——那是下载格式选择器，本地视频不需要
- `VideoSummary.vue` 只加了 `mode` / `jobId` / `initialData` 三个 props 和一处分支，其余原样

## 五、后续增补的功能

第一版交付后按需求陆续增补：

### 多格式支持

从只支持 MP4 扩展到 **23 种容器格式**（MP4/MOV/MKV/AVI/WebM/FLV/WMV/TS/M4V/ASF/F4V/MTS/M2TS/MPG/MPEG/M2V/3GP/3G2/OGV/RM/RMVB/VOB/DIVX）。

底层是 ffmpeg 解封装，这些格式本来就支持，之前的限制纯粹在校验层。

**MIME 策略**：浏览器对 MKV/FLV/TS 经常给不出 MIME（空）或给 `application/octet-stream`，所以 MIME 只用来挡明显不对的类型（文本/图片/压缩包/可执行文件），**不作为主要依据**。真正的把关是 ffprobe——它确认文件确实含视频流和音轨，所以改后缀名伪装的文件依然会被挡下。

### 管理员账号

需求是「管理员能绕过自己的使用限制」，身份认定用环境变量。

在 `.env` 配置：

```bash
ADMIN_EMAILS=you@example.com,teammate@example.com
```

命中的**已注册账号**即为管理员。**不创建账号、不设独立密码、不改数据库**——管理员身份是贴在已有账号上的标签。

管理员的限制放宽情况（在线视频和本地视频两边都生效）：

| 限制 | 普通用户 | 管理员 |
|---|---|---|
| 每日 AI 总结次数 | 3 次 | 不限，且不计数 |
| 单用户并发任务数 | 1 个 | 不限 |
| 视频时长 | 60 分钟 | 不限 |
| 文件大小 | 500MB | **放宽到 5GB，不是无限** |

注意文件大小是**放宽**而非取消——`ADMIN_MAX_FILE_SIZE_MB` 默认 5000，超出同样会被拦截。保留一个有限上限是刻意的，避免误操作把磁盘写满（参见下文「500MB 限制原本形同虚设」）。

**边界**：管理员只放宽自己的用量，**看不了别人的数据**——任务归属校验对管理员同样生效（访问他人任务返回 404）。

> ⚠️ 这里为了让管理员在在线视频那边也免配额，在 `api_summarize.py` 的 `_check_summary_permission()` 里加了 3 行早退。这是本次唯一修改的既有业务文件。`ADMIN_EMAILS` 为空时该分支永不触发，对普通用户零影响。

### 结果持久化（浏览器本地）

**问题**：任务结果只存在浏览器内存 + 服务端内存，刷新页面（F5）、关标签页、退出登录都会全丢。

**方案**：`localStorage` 缓存，不动数据库。

- 按 `user_id` 隔离，换账号登录读不到别人的
- 2 小时过期，与服务端任务 TTL 对齐，避免「前端还在、后端早没了」的错位
- 只缓存文字结果（字幕/总结/导图），**视频从来不缓存**
- **恢复走缓存，不重新调用 AI**，因此刷新和重新登录都不会重复扣配额
- 点「删除」会同时清掉缓存

**局限**：换浏览器/换设备看不到。要跨设备就得做服务端历史记录（需要建表）。

## 六、开发过程中发现并修复的问题

以下问题都是在测试阶段暴露的，值得记录，因为它们揭示了一些容易踩的坑。

### 🔴 严重：500MB 限制原本形同虚设，未登录也能写爆磁盘

**现象**：用**无效 token** 发 300MB 请求，服务器返回 401，但 **242MB 已经写进磁盘**（实测数据）。

**原因**：FastAPI 会在执行路由函数**和鉴权依赖**之前，先 `await request.form()` 把整个 multipart 解析完；Starlette 对「文件」类型的 part 不设上限，会一路写进系统临时目录。也就是说写在处理函数里的 `MAX_FILE_SIZE` 校验永远是**事后检查**——字节早就落盘了。

任何人不需要有效凭据，就能靠持续发大请求把服务器磁盘写满。

**修复**：新增 ASGI 中间件 `UploadSizeLimitMiddleware`，在 body 被解析之前拦截：

1. **鉴权前置**——先做一次廉价的 JWT 校验（不查库），匿名请求连一个字节都传不进来
2. **Content-Length 预检**——超限直接 413
3. 没有 Content-Length（chunked）时边收边计数，超限即断开输入流

中间件只匹配 `/api/local/upload`，且注册在 CORS **内层**，对其他所有接口零影响。

**修复后实测**：600MB 超限 → 413、无效 token → 401、无 Authorization → 401，三种情况**磁盘增长均为 0.0 MB**。

### 🟡 前端状态不同步（一类问题，三个入口）

**现象**：删除本地视频后，结果区清空了，但上传区仍显示「字幕已生成，AI 分析结果见右侧」，而右侧已空，且卡在无法重新选文件的状态。

**原因**：`App.vue` 清空了自己的 `localVideo`，但没有重置 `HeroSection` 内 `LocalUpload` 子组件的内部状态。`LocalUpload` 是 `v-show` 挂载的，切 Tab 不会卸载。

**教训**：这个 bug 最初只在「删除」路径被发现和修复，后来的代码审查发现**切换来源 Tab** 和**退出登录**两条路径有完全相同的问题。修一处不等于修完。

**修复**：收敛成一个 `clearLocal()`，所有入口统一调用，保证「清 App 侧状态」和「重置上传区」永远成对出现。

### 🟡 过期回调污染界面

上传/轮询过程中删除任务，在飞的异步回调回来后会把过期状态写回界面。

**修复**：`LocalUpload.vue` 引入 `runId`，每次上传/重置自增；异步回调回来时若 `runId` 已变则直接丢弃结果。

### 🟡 任务删除后目录残留

删除任务不会通知后台线程，Windows 下正在被 ffmpeg 占用的文件删不掉，留下空壳目录。

**修复**：`_process_job` 在各阶段之间加取消检查点（任务被移出 `_jobs` 即视为取消），并在成功/失败/取消三条路径上都回收工作目录。

### 🟡 过期清理会误删处理中的任务

原清理逻辑只看 `created_at`，长视频转写可能超过 TTL，会把后台线程正在读的源文件删掉。

**修复**：清理时跳过 `ACTIVE_STATUSES`（pending/probing/extracting/transcribing）的任务。

### 🟡 错误信息泄露服务器路径

ffmpeg 的 stderr 原文回传给前端，含服务器绝对路径等内部信息。

**修复**：外部工具的原始报错只写服务端日志，前端只看到固定的中文提示。

## 七、环境相关的坑

### Anaconda 的 OpenMP 冲突（必须处理）

Anaconda 的 MKL 与 ctranslate2 各自带了一份 OpenMP 运行时，同一进程加载两份会**直接抛 `OMP: Error #15` 并终止进程**。

`local_video.py` 顶部设置了 `KMP_DUPLICATE_LIB_OK=TRUE`，必须在 faster-whisper / ctranslate2 被导入**之前**执行。这是该组合的通行解法，实测输出正确。

### 安装 faster-whisper 的连带影响

`pip install faster-whisper` 会把 `protobuf` 从 4.25.3 升级到 7.35.1，导致同环境的 `streamlit 1.37.1` 出现依赖冲突警告。与本项目无关，但同一环境跑 streamlit 需留意。

### 测试脚本的 5 秒陷阱（不是服务端问题）

排查一个「并发上限失效」的假阴性时发现：本机上 `httpx.get()` **每次新建 Client 要 ~5 秒**（Windows 下加载 SSL 信任库），复用同一个 `Client` 只要 0.001 秒。

这个开销曾导致：

1. 并发测试的两次上传间隔被拉到 10 秒，第一个任务早就跑完了，测出假阴性
2. 早期报告的「413 拒绝耗时 5.9 秒」被灌水——实际拒绝是毫秒级

**写测试脚本务必复用 `httpx.Client`。**

## 八、测试情况

全部为真实运行验证，非静态检查。

### 后端接口测试

| 套件 | 覆盖内容 |
|---|---|
| API 全链路 | 上传 → 轮询 → SSE 总结 → 问答 → 越权 → 删除；事件序列与在线视频一致性校验 |
| 上传防护 | 超限文件、无效 token、无 token 三种场景的磁盘增长监控 |
| 清理路径 | 正常完成 / 处理中删除 / 无音轨失败 三条路径的残留检查 |
| 加固项 | 并发上限、ASR 就绪探测、错误信息脱敏 |
| 多格式 | 8 种容器格式端到端转写 + 伪装文件拦截 |
| 管理员 | 限额差异、并发绕过、配额不计数、归属隔离 |

### 关键结论

- 8 种主流格式（MP4/MOV/MKV/AVI/WebM/FLV/WMV/TS）**全部走通完整链路**并正确识别出语音文本
- 三种攻击场景磁盘增长 **0.0 MB**
- 三条清理路径 `uploads` 残留 **0**
- 管理员的 `daily_summary_count` 在数据库中**始终为 0**，确认未走计数逻辑
- 普通用户限额（500MB / 60 分钟 / 3 次 / 1 并发）**完全未受影响**
- 结果持久化：刷新 + 退出重登后，数据库中该账号 `daily_summary_count` **仍为 1**，确认恢复不重复扣配额

### 浏览器端到端验证

真实浏览器完整走查：上传 → 进度 → 字幕 → 四个 Tab（总结/字幕/导图/问答）→ 删除，全程零弹窗错误。

原有在线解析同步回归：YouTube 链接正确解析出标题、UP 主、播放量、时长与 15 个清晰度选项。

## 九、当前存在的问题

### 待决策

**AI 总结的配额在调用大模型之前就扣除**，模型报错时用户白丢一次。

未修改的原因：修它需要在 `database.py` 增加退款函数，触及「不随意修改数据库 / 不修改会员系统」的约束；且**现有的在线视频总结是完全相同的行为**，改动等于同时变更两边的既有语义。

可选方案：① 保持现状（与既有行为一致）② 只给本地视频加失败退款（两种来源行为不一致）③ 两边一起加（行为统一，但要动 `database.py` 和 `api_summarize.py`）。

### 已知限制

| 限制 | 说明 |
|---|---|
| CPU 转写慢 | 约 0.4x 实时，60 分钟视频约需 25 分钟。有 GPU 时设 `WHISPER_DEVICE=cuda` 可提速 5–10 倍 |
| 不支持多进程部署 | 任务状态存内存，`--workers > 1` 时上传落到 A 进程、查状态打到 B 进程会 404。当前单进程部署没问题 |
| 结果不跨设备 | 持久化基于浏览器 `localStorage`，换浏览器/设备看不到 |
| 串行处理排队 | 单线程处理，多人同时上传需要排队，长视频会让后面的人等较久 |

## 十、下一步优化建议

按性价比排序：

1. **上 GPU**：`WHISPER_DEVICE=cuda` + `WHISPER_COMPUTE_TYPE=float16`，转写提速 5–10 倍，是体验提升最大的一项
2. **中文内容调大模型**：`WHISPER_MODEL_SIZE=small` 或 `medium`，中文准确率明显更好（代价是更慢）
3. ~~**排队可见性**~~ ✅ **已完成**：`/api/local/status` 返回 `queue_position`（前面还有几个任务）与 `eta_seconds`（预计等待秒数，按时长 × 实测系数 0.5 折算），前端排队时显示「排队中：前面还有 N 个任务，预计等待约 X 分钟」。实现在 `local_video.queue_info` + `LocalUpload.vue`
4. **服务端历史记录**：需要建表存字幕与总结，换设备也能看。这是原计划中「暂不开发」的上传历史，做之前需要重新界定「不长期保存用户数据」的边界——字幕全文要存多久
5. **多进程部署支持**：任务状态迁到 Redis，解除单进程限制
6. **说话人分离**：会议录像场景价值高，但属于「高级视频理解」，第一版明确不做
