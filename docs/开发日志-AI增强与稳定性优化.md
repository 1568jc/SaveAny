# 开发日志：AI 功能增强与稳定性优化

> 本文档记录一轮二次开发的完整过程：AI 功能做深（章节大纲 / 问答溯源 / 字幕翻译）、在线视频无字幕时的语音识别回退、yt-dlp 自动升级与友好报错、分享口令兼容、Whisper 繁体转简体。
>
> 重点记录那些"看起来奇怪但有原因"的写法和踩过的坑，后续接手的人不用重新踩一遍。

---

## 一、需求背景

起点是一次线上故障：B 站视频解析突然全部报 `HTTP Error 412: Precondition Failed`——本地 yt-dlp 版本（2026.03.17）太旧，B 站接口风控升级后旧版请求直接被拒。由此牵出一串改进：

1. **稳定性**：yt-dlp 依赖的平台接口随时会变，人工升级太被动
2. **AI 功能深度**：对标 BibiGPT 等竞品，补章节时间戳大纲、问答引用溯源、字幕翻译
3. **抖音 AI 总结完全不可用**：抖音没有字幕轨道，yt-dlp 也不支持其用户页 URL，AI 总结对抖音形同虚设
4. **体验细节**：分享口令粘贴被浏览器拦截、Whisper 识别输出繁体

---

## 二、稳定性工程

### yt-dlp 启动自动升级（ytdlp_manager.py）

**关键设计：检查升级必须在任何 `import yt_dlp` 之前执行**，否则进程内加载的还是旧版，升了也白升。所以：

- `ytdlp_manager` 模块自身**不 import yt_dlp**，版本号用 `importlib.metadata.version()` 读
- `main.py` 在 `from downloader import ...`（内部 import yt_dlp）之前调用 `auto_upgrade_on_startup()`
- 可用 `YTDLP_AUTO_UPGRADE=false` 关闭

### 友好报错（friendly_error.py）

把 yt-dlp 的英文原始报错映射成中文提示（412/403/404/DNS 失败/不支持的平台等）。注意：**后端 `error` 字段只放纯文案，不要再带"解析失败："前缀**——前端弹窗会自己加前缀，之前双重前缀"解析失败：解析失败："就是这么来的。

### 健康检查增强

`/api/health` 返回 yt-dlp 当前/最新版本、是否过期、ffmpeg 是否可用。最新版本号带 1 小时缓存，避免高频调用打 PyPI。

## 三、AI 功能做深

### 3.1 带时间戳的转写稿

之前 prompt 只用 `full_text`（无时间戳），分段里的 `start/end` 全被丢弃。现在统一经 `_build_timestamped_transcript(segments)` 拼成 `[mm:ss] 文本` 逐行格式喂给模型，总结/问答共用。

- 总结：prompt 要求输出 `- [mm:ss] 章节标题：概括` 的章节大纲，前端把 `[mm:ss]` 渲染成蓝色时间徽章
- 问答：prompt 要求引用具体内容时标注 `【mm:ss】`，前端同样渲染
- 站内没有视频播放器，时间戳只做展示与核对，不做点击跳转

### 3.2 字幕翻译（/api/translate）

- 新增 `translate_stream()`：按 ~6000 字符切块（按行断开不截句子），逐块流式调用 DeepSeek
- 权限与 AI 总结共用配额（免费用户每次计 1 次），防止匿名白嫖 token
- 前端入口在「字幕文本」Tab，按字幕语言自动决定目标语言（中→英，其他→中）

### 3.3 ⚠️ 关键坑：DeepSeek thinking 会耗尽 max_tokens

**这是本轮最重要的一个发现。** `deepseek-v4-flash` 是思考型模型，流式响应会先输出大量 `reasoning_content`（思考过程），且**思考 token 计入 max_tokens**。

实测：长转写稿的总结请求，4080 个 chunk 全是 reasoning、`content` 为零、`finish_reason=length`——4096 额度全被思考烧光，正文一个字没有。短内容刚好不超，所以表现为**偶发性空输出**，非常难排查。

修复：所有 DeepSeek 调用加 `extra_body={"thinking": {"type": "disabled"}}`。总结/翻译/问答这类任务不需要深度思考，关掉后除了问题消失，**总结耗时还从 ~48s 降到 ~18s**，token 成本也更低。

## 四、在线视频 ASR 回退（online_asr.py）

### 4.1 触发条件

- 抖音链接：直接走 ASR（平台无字幕轨道，yt-dlp 也不支持其用户页）
- 其他平台：先取平台字幕，取不到再 ASR 兜底
- 产出结构与 `SubtitleExtractor.extract()` 完全一致，下游零改动

### 4.2 抖音音源：必须用视频本体，不能用 music.play_url

抖音元数据里的 `music.play_url` 是**背景音乐的独立音源**——说话类视频拿它转写，得到的是 BGM 歌词而不是人声。正确路径是下载视频本体（play_addr）→ ffmpeg 抽音轨。

### 4.3 CDN 直链优先，避免重复请求平台 API

前端解析成功时结果里带 `_direct_url`（无水印 CDN 直链），总结时回传给后端，ASR 直接下载它，**整个过程不碰抖音 API**。

踩过的坑：自己用 httpx + 精简请求头下载 CDN 会 403——抖音 CDN 的 WAF 对请求特征敏感。修复为复用 `DouyinParser` 的 requests 会话与完整请求头（与「立即下载」完全相同的特征）。直链 403/过期时再回退到重新解析取新鲜直链。

### 4.4 顺手重构

`DouyinParser` 新增 `parse_item()`：一次元数据请求同时满足解析与下载（原先 parse + download 各请求一次，双倍风控压力）。

## 五、分享口令兼容

抖音分享出来的是"文本 + 链接"混排口令，两个地方都要兼容：

1. **路由判断**：`is_douyin_url()` 原先对整段文本做 `urlparse`，口令开头是版本号文本导致识别不了抖音域名，整段话被丢给 yt-dlp generic 解析器报出一整屏口令原文。修复：先从文本提取第一个 URL 再判断。`/api/parse`、`/api/download`、`/api/direct-url` 的 yt-dlp 路径也统一先提取洁净 URL
2. **前端输入框**：`type="url"` 会被浏览器原生校验拦下（口令含中文），改为 `type="text"`

## 六、Whisper 繁体转简体

Whisper 识别普通话经常默认输出繁体（训练数据里繁体占比不小）。双保险：

1. 转写时加 `initial_prompt="以下是简体中文普通话的语音转写。"` 引导简体输出
2. 结果经 OpenCC `t2s` 强制繁转简（仅检测语言为 `zh` 时生效）

逻辑收敛在 `local_video.transcribe()` 内，本地上传与在线 ASR 回退两条链路都覆盖。新增依赖 `opencc-python-reimplemented`（纯 Python）。

## 七、测试结果

| 场景 | 结果 |
|---|---|
| B 站视频总结 | 546 个 summary 事件流式输出，章节时间戳 [00:00]–[02:59] 正确 |
| 问答溯源 | 回答中带【00:00】【01:05】等引用，时间点准确 |
| 字幕翻译 | 中→英流式输出正确，quota 正常扣减 |
| ASR 回退（yt-dlp 路径） | B 站视频下载音频 → 95 条带时间戳字幕，语言检测 zh |
| ASR 回退（抖音直链路径） | 本地 HTTP 服务器模拟 CDN：下载 → ffprobe → 抽音轨 → 转写全通 |
| 繁转简 | "文明進步的歷史…" → "文明进步的历史…"，英文不受影响 |
| 分享口令 | 正确路由到抖音解析器，不再误进 yt-dlp |
| 友好报错 | 无效域名返回"无法访问该网站（域名解析失败）…" |

## 八、遗留问题

1. **抖音 IP 级风控**：公开接口对服务端 IP 敏感（高频请求后短链重定向都会被掐），间歇性失效。本地自用等几小时可恢复；上线需配 Cookie 池或代理池
2. **时间戳不可跳转**：站内无视频播放器，章节/引用时间戳仅展示
3. **ASR 回退无进度反馈**：whisper 转写期间前端只有静态"正在提取视频字幕…"提示，长视频体验一般（本地视频有百分比进度，在线回退还没接）
4. 测试期在本地数据库注册了几个测试账号（`verify*@test.com`），如介意可删 `backend/data/app.db` 重建
