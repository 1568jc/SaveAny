## 2. 技术栈选型

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 前端框架 | Vue 3 + Vite | 轻量、上手快、生态成熟 |
| CSS 框架 | Tailwind CSS | 快速构建精美 UI，无需写大量自定义 CSS |
| Markdown 渲染 | marked + @tailwindcss/typography | marked 转 HTML + prose 类精美排版 |
| 思维导图 | markmap-lib + markmap-view | 开源成熟，支持 Markdown 输入，交互性好 |
| 后端框架 | FastAPI (0.135+) | 异步高性能、原生 SSE 支持、Python 生态 |
| 核心能力 | yt-dlp | 14w+ Star，支持 1800+ 网站，社区活跃 |
| AI 大模型 | DeepSeek (deepseek-v4-flash) | 兼容 OpenAI 协议，通过 openai SDK 调用；已关闭 thinking（思考 token 会耗尽 max_tokens 导致空输出），模型名走 `DEEPSEEK_MODEL` 环境变量 |
| 语音识别 | faster-whisper | 本地视频转文字 + 在线无字幕视频回退。完全本地运行，无需 API Key、无调用费用、音频不出本机；CPU 下约 0.4x 实时 |
| 中文繁简转换 | opencc-python-reimplemented | Whisper 识别普通话常输出繁体，用 OpenCC `t2s` 统一转简体；纯 Python，无系统依赖 |
| 音视频处理 | ffmpeg / ffprobe | 本地视频的格式把关与音频提取。ffprobe 探测真实媒体信息（是否含视频流/音轨、时长），ffmpeg 解封装出 16kHz 单声道 WAV 供语音识别 |
| 数据库 | 无 | 轻量设计，无需持久化存储 |

### 3.4 AI 视频总结（SSE 流式）

```
POST /api/summarize
Content-Type: application/json

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "language": "zh",
    "direct_url": ""        // 可选。前端解析时拿到的 CDN 直链（抖音用），
                            // 传入后 ASR 回退不再重复请求平台 API
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - subtitle  → 字幕数据（含 segments 时间戳列表和 full_text）
  - summary   → 总结摘要（流式 token，逐字输出；含 [mm:ss] 章节时间戳大纲）
  - mindmap   → 思维导图 Markdown（一次性返回）
  - quota     → 剩余次数（remaining / limit）
  - done      → 完成信号
  - error     → 错误信息

事件顺序：subtitle → summary(多次) → mindmap → quota → done

无平台字幕时的回退（见 7.6）：
  - 抖音 → 直接走语音识别（该平台无字幕轨道，yt-dlp 亦不支持其用户页）
  - 其他平台 → 先取平台字幕，取不到再下载音频走语音识别
```

### 3.5 AI 视频问答（SSE 流式）

```
POST /api/chat
Content-Type: application/json

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "question": "这个视频用了什么技术栈？",
    "subtitle_text": "",
    "segments": null        // 可选。传入带时间戳的字幕分段后，
                            // 回答会引用【mm:ss】时间点（问答溯源）
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - answer    → AI 回答（流式 token，引用处以【mm:ss】标注时间点）
  - done      → 完成信号
  - error     → 错误信息
```

> 本地上传视频的问答**直接复用本接口**，后端零改动：代码里只要 `subtitle_text` 非空就完全不使用 `url`，前端把语音识别得到的字幕全文（及分段）传进来即可。

### 3.11 字幕翻译（SSE 流式）

```
POST /api/translate
Authorization: Bearer <token>   （必需；与 AI 总结共用配额规则：
                                 免费用户每次计 1 次每日配额，VIP/管理员不限）
Content-Type: application/json

Request:
{
    "segments": [{"start": 0.28, "end": 1.0, "text": "字幕文本"}, ...],
    "target_lang": "en"     // zh=翻译成中文，en=翻译成英文
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - translate → 译文（流式 token；按 ~6000 字符切块，块内流式输出）
  - quota     → 剩余次数
  - done      → 完成信号
  - error     → 错误信息（含 need_login / need_vip 标记）
```

> 前端入口在「字幕文本」Tab：根据字幕语言自动决定目标语言（中文→英文，其他→中文），译文流式显示在原文上方。

### 3.6 获取本地上传配置

```
GET /api/local/config
Authorization: Bearer <token>   （可选；带上登录态时返回「该用户实际生效」的限额）

Response (200):
{
    "success": true,
    "data": {
        "max_file_size": 524288000,
        "max_file_size_mb": 500,
        "max_duration": 3600,
        "max_duration_minutes": 60,
        "allowed_extensions": [".3g2", ".3gp", ".asf", ".avi", ".divx", "..."],
        "asr_available": true,
        "asr_unavailable_reason": "",
        "is_admin": false
    }
}
```

- 管理员（`ADMIN_EMAILS` 命中）返回的 `max_file_size` 取 `ADMIN_MAX_FILE_SIZE_MB`（默认 5000MB），`max_duration` 为 `0` 表示不限时长
- `asr_available` 由服务端实探 ffmpeg / ffprobe / faster-whisper 是否就位，前端据此决定是否放开上传入口

### 3.7 上传本地视频

```
POST /api/local/upload
Content-Type: multipart/form-data
Authorization: Bearer <token>   （必须登录）

Request:
  file: <视频文件>

Response (200):
{
    "success": true,
    "data": {
        "job_id": "3f2a1c9e5b7d4a08b6c2e1f09d3a4b5c",
        "filename": "会议录像.mp4",
        "filesize": 104857600,
        "status": "pending"
    }
}

Response (400): 扩展名不在白名单 / MIME 明显不对 / 文件为空 / 超出大小上限
Response (401): 未登录或 token 无效（在请求体落盘之前拦截）
Response (413): 请求体超过大小上限（在请求体落盘之前拦截）
Response (429): 该用户已有任务在处理中（管理员不受限）
Response (503): 服务器未安装 ffmpeg 或 faster-whisper

错误体统一为：
{
    "detail": {"success": false, "error": "文件过大，最大支持 500MB"}
}
```

落盘后**立即返回** `job_id`，ffprobe 校验 / 音频提取 / 语音识别在后台串行执行，由 3.8 轮询进度。

### 3.8 查询本地视频处理状态

```
GET /api/local/status/{job_id}
Authorization: Bearer <token>

Response (200):
{
    "success": true,
    "data": {
        "job_id": "3f2a1c9e5b7d4a08b6c2e1f09d3a4b5c",
        "status": "transcribing",
        "progress": 61,
        "stage_text": "正在识别语音，生成字幕... 53%",
        "error": null,
        "filename": "会议录像.mp4",
        "filesize": 104857600,
        "duration": 1832.5,
        "duration_string": "30:32",
        "segment_count": 0
    }
}

status 取值：
  pending      → 排队中
  probing      → ffprobe 校验中
  extracting   → 提取音频中
  transcribing → 语音识别中
  done         → 处理完成（segment_count 为字幕分段数）
  failed       → 处理失败（error 为用户可读的中文提示）

Response (404):
{
    "detail": {"success": false, "error": "任务不存在或已被清理，请重新上传"}
}
```

响应中**不包含任何服务器文件路径**；任务归属校验对所有人生效，访问他人任务一律 404（管理员同样如此）。

### 3.9 删除本地视频任务

```
DELETE /api/local/job/{job_id}
Authorization: Bearer <token>

Response (200):
{
    "success": true,
    "data": {
        "job_id": "3f2a1c9e5b7d4a08b6c2e1f09d3a4b5c",
        "deleted": true
    }
}

Response (404):
{
    "detail": {"success": false, "error": "任务不存在或已被删除"}
}
```

删除会同时移除内存中的任务记录与残留的工作目录；处理中的任务在后台线程的下一个检查点自行中止。

### 3.10 本地视频 AI 总结（SSE 流式）

```
POST /api/local/summarize
Content-Type: application/json
Authorization: Bearer <token>

Request:
{
    "job_id": "3f2a1c9e5b7d4a08b6c2e1f09d3a4b5c",
    "language": "zh"
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - subtitle  → 字幕数据（含 segments 时间戳列表和 full_text，subtitle_type 为 "asr"）
  - summary   → 总结摘要（流式 token，逐字输出）
  - mindmap   → 思维导图 Markdown（一次性返回）
  - quota     → 剩余次数（remaining / limit；管理员的 remaining 为 -1）
  - done      → 完成信号
  - error     → 错误信息（任务不存在 / 仍在处理中 / 处理失败 / 配额用尽）

事件顺序：subtitle → summary(多次) → mindmap → quota → done
```

**本接口的事件类型、事件顺序、每个事件的数据结构均与 3.4 的 `/api/summarize` 完全一致**——这是刻意保持的契约。正因为一致，前端 `VideoSummary.vue` 的流式渲染、字幕导出（SRT/VTT/TXT）、思维导图导出（PNG/SVG）逻辑才能原样复用，两种视频来源之间只替换了请求函数。

配额与在线视频共用同一套规则（VIP 无限、免费用户每日 N 次），管理员不计数。

## 4. 下载模式策略

系统自动选择最优下载模式：

1. **优先尝试直链模式**：调用 `/api/direct-url` 获取直链
   - 如果成功且直链可用 → 浏览器直接下载（不占服务器带宽）
2. **回退到代理模式**：如果直链不可用或有防盗链
   - 调用 `/api/download` → 服务端下载后流式传输给用户

## 7. AI 视频总结模块设计

### 7.1 字幕提取策略

```
用户输入 URL 或分享口令（先从文本中提取第一个 URL 再判断路由）
    ├─ 抖音？ → 直接走语音识别回退（该平台无字幕轨道）：
    │           CDN 直链下载视频（前端解析结果里带的 _direct_url）
    │           → 失败则重新解析取新鲜直链
    │           → ffprobe 校验 → ffmpeg 抽 16kHz WAV → whisper 转写
    ├─ B站视频？ → B站专用 API（x/v2/dm/view）获取 CC 字幕 / AI 字幕
    │              ├─ 成功 → 返回字幕
    │              └─ 失败 → 回退到 yt-dlp
    └─ 其他平台 → yt-dlp 提取字幕
                   ├─ 人工字幕（优先：zh > en > ja > ko > 其他）
                   ├─ 自动字幕（同上优先级）
                   └─ 无字幕 → 语音识别回退（yt-dlp 下载 bestaudio → whisper）
```

字幕格式：VTT → 解析为结构化分段 `[{start, end, text}, ...]`

### 7.2 AI 调用流程

1. 构建**带时间戳的转写稿**（`[mm:ss] 文本` 逐行拼接，截断至 15000 字符；无 segments 时退化为纯文本）
2. 调用 DeepSeek API（stream=True）流式生成总结摘要（含章节时间戳大纲）
3. 调用 DeepSeek API 生成思维导图 Markdown
4. 通过 SSE 实时推送给前端

> **关键坑：必须关闭 DeepSeek 的 thinking**。deepseek-v4 系列是思考型模型，思考过程（reasoning_content）计入 max_tokens；长转写稿会让思考烧完全部 4096 额度，正文零输出（finish_reason=length），表现为"总结偶发为空"。所有调用统一加 `extra_body={"thinking": {"type": "disabled"}}`，顺带把总结耗时从 ~48s 降到 ~18s。

### 7.6 章节大纲、问答溯源与字幕翻译

- **章节化总结**：转写稿带 `[mm:ss]` 时间戳后，prompt 要求按 `- [mm:ss] 章节标题：概括` 输出章节大纲；前端把 `[mm:ss]` 渲染为蓝色时间徽章
- **问答溯源**：问答 prompt 要求引用具体内容时标注 `【mm:ss】`，前端同样渲染为徽章；站内无播放器，时间戳只做展示不做跳转
- **字幕翻译**：`translate_stream()` 将字幕按 ~6000 字符切块（按行断开），逐块流式翻译，块间顺序执行；权限与总结共用配额，防止接口被白嫖 token
- **无字幕回退（online_asr.py）**：产出的字幕结构与 `SubtitleExtractor.extract()` 完全一致，下游总结/导图/问答/导出零改动；时长上限与本地视频一致（60 分钟）

> 抖音回退的音源必须用**视频本体**（play_addr），不能用 `music.play_url`——后者是背景音乐的独立音源，没有人声。

### 7.3 SSE 数据传输

- **summary / answer 事件**：token 通过 `json.dumps()` 编码后发送，避免换行符被 SSE 协议拆行导致前端丢失格式
- **前端解析**：严格按照 SSE 规范处理，`data:` 行用 `\n` 拼接，空行触发事件派发，`summary` / `answer` 数据先 `JSON.parse` 解码

### 7.4 前端渲染

- **总结摘要**：marked 解析 Markdown → `@tailwindcss/typography` prose 类排版 + 自定义样式覆盖（h1/h2/h3/blockquote/code/pre/table/a 等），流式打字机效果
- **字幕文本**：带时间戳的列表，支持展开/收起，支持下载字幕文件（SRT / VTT / TXT 三种格式）
- **思维导图**：markmap-lib 转换 Markdown → markmap-view 渲染 SVG，支持全屏展示（Fullscreen API），支持下载高清 PNG（4K+）和 SVG 矢量图
- **AI 问答**：对话式 UI，流式输出 + 光标闪烁动画，AI 回复使用 prose 排版

### 7.5 思维导图导出策略

- **PNG 导出**：通过 `<g>` 根节点的 `getBBox()` 获取完整内容边界（不受用户缩放/平移影响）→ 将 `foreignObject` 替换为 SVG `<text>` 元素（规避 Canvas tainted 安全限制）→ 设置完整 `viewBox` + 4x 以上缩放 → Canvas 绘制 → `toBlob()` 导出
- **SVG 导出**：克隆 SVG DOM → 通过 `getBBox()` 重设完整 `viewBox` → 内联 markmap CSS → 序列化为独立 SVG 文件
- **全屏展示**：使用浏览器原生 Fullscreen API，全屏后调用 `markmapInstance.fit()` 自适应

## 8. 本地视频上传解析模块设计

在「在线视频链接」之外新增第二种视频来源：**本地上传视频**（本地录屏、会议录像、下载好的课程、手机拍摄素材等没有公开链接的视频）。

### 8.1 设计目标与复用策略

整条 AI 流水线只有**一个契约**——`SubtitleExtractor.extract()` 的返回结构，它是总结、思维导图、问答、字幕导出的唯一输入：

```python
{
    "has_subtitle": bool,
    "language": str,
    "subtitle_type": "manual" | "auto" | "none" | "asr",
    "segments": [{"start": float, "end": float, "text": str}, ...],
    "full_text": str
}
```

因此本模块的设计目标只有一条：**让语音识别的产出与该结构完全同构**。做到这一点后，后续功能全部零改动复用：

| 能力 | 复用方式 |
|------|----------|
| AI 总结 / 思维导图 | 复用 `summarizer.VideoSummarizer`，与 `/api/summarize` 同一份实现 |
| AI 视频问答 | 完全复用 `/api/chat`，后端一行未改（`subtitle_text` 非空时不使用 `url`） |
| 字幕导出（SRT/VTT/TXT） | 复用前端已有导出逻辑 |
| 思维导图导出（PNG/SVG） | 复用 7.5 的导出策略 |

新增的唯一差异是 `subtitle_type` 增加了取值 `"asr"`（表示语音识别生成），前端据此把标签显示为「AI 识别字幕」，其余渲染路径与在线视频字幕一致。

模块边界：`downloader.py` / `douyin.py` / `summarizer.py` 完全未改动，数据库表结构零改动，新增路由全部挂在 `/api/local/*` 独立前缀下，与原有路由零冲突。

### 8.2 处理流水线

```
本地视频上传（multipart，1MB 分块写盘，不整个进内存）
    ↓  ffprobe 校验：真的是视频？含视频流与音轨？时长合规？
    ↓  ffmpeg 提取音频：16kHz 单声道 PCM WAV（Whisper 原生输入格式）
    ↓  删除视频文件（不长期保存用户视频）
    ↓  faster-whisper 转写：segments[{start, end, text}] + 语言自动检测
    ↓  删除音频文件
    ↓  ★ 产出与 SubtitleExtractor.extract() 完全同构的字幕结构 ★
    ↓
汇入现有流程：AI 总结 / 思维导图 / 视频问答 / 字幕导出
```

各阶段对应的 `status` 与进度区间：`probing`(5%) → `extracting`(15%) → `transcribing`(20%~99%) → `done`(100%)。转写进度按 `segment.end / 总时长` 估算，前端轮询 3.8 展示。

转写参数：`beam_size=5`、开启 VAD 过滤（`min_silence_duration_ms=500`）以跳过静音段；语言默认自动检测，可用 `WHISPER_LANGUAGE` 固定。

### 8.3 语音识别选型

这是本次唯一无法复用现有能力的环节——DeepSeek 没有 ASR 接口，现有 API Key 用不上。

| 方案 | 代价 | 速度（CPU） | 结论 |
|------|------|------------|------|
| **faster-whisper** | 新增 `faster-whisper` + `ctranslate2` 依赖，首次运行自动下载模型 | 约 0.4x 实时 | **采用** |
| openai-whisper | 可复用环境中已装的 torch，但为 CPU 版 | 比上者慢 4–8 倍 | 否决：60 分钟视频要跑 30–60 分钟 |
| 第三方 ASR API | 需要新 API Key + 按量计费 + 音频上传到第三方 | 最快 | 否决：与「不长期保存用户视频」的隐私定位冲突 |

选择 faster-whisper 的理由：完全本地运行、无需 API Key、零调用费用、音频不出本机（契合隐私定位），CPU 下速度可接受。

可调参数全部走环境变量，无需改代码：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `WHISPER_MODEL_SIZE` | `base` | 模型大小，中文内容建议 `small` / `medium`（更准但更慢） |
| `WHISPER_DEVICE` | `cpu` | 有 NVIDIA 显卡时设 `cuda`，转写提速 5–10 倍 |
| `WHISPER_COMPUTE_TYPE` | `int8` | GPU 下建议 `float16` |
| `WHISPER_LANGUAGE` | 空 | 空表示自动检测语言 |
| `HF_ENDPOINT` | — | 模型下载走国内镜像 |
| `ADMIN_EMAILS` | 空 | 管理员邮箱（逗号分隔），命中的**已注册账号**不受次数/并发/大小/时长限制 |
| `ADMIN_MAX_FILE_SIZE_MB` | `5000` | 管理员的文件大小上限（仍保留有限值，避免误操作写满磁盘） |

> 环境相关：Anaconda 的 MKL 与 ctranslate2 各自带了一份 OpenMP 运行时，同进程加载两份会直接抛 `OMP: Error #15` 并终止进程。`local_video.py` 在导入 faster-whisper **之前**设置了 `KMP_DUPLICATE_LIB_OK=TRUE` 规避。

**中文繁转简**：Whisper 识别普通话时经常默认输出繁体。双保险处理——转写时加 `initial_prompt="以下是简体中文普通话的语音转写。"` 引导模型输出简体；识别结果再经 OpenCC `t2s` 强制繁转简（仅当检测语言为 `zh` 时启用，其他语言原样保留）。该逻辑在 `transcribe()` 内统一生效，本地上传与在线视频 ASR 回退两条链路都覆盖。

### 8.4 任务状态管理

**不写数据库**，任务状态存进程内存字典（key = `job_id`），理由有三：数据库表结构不做改动是硬约束；第一版不做上传历史；契合「不长期保存用户视频」——进程退出即全清。

- **串行处理**：`ThreadPoolExecutor(max_workers=1)`。语音识别是 CPU 密集型，并行只会互相拖慢；同时限制**单用户同时进行中的任务数为 1**，避免一个账号把队列占满（管理员不受此限）
- **文件生命周期**：视频文件在**音频提取完成后立即删除**，音频文件在**转写完成后立即删除**，内存中只保留文字结果
- **TTL**：任务结果保留 2 小时；除上传时顺带触发清理外，另有每 5 分钟一次的后台定期清理任务，避免服务空闲期过期任务一直占着内存
- **清理不误伤**：回收时跳过 `ACTIVE_STATUSES`（pending/probing/extracting/transcribing）的任务——长视频转写可能超过 TTL，误删会把后台线程正在读的源文件删掉
- **取消检查点**：`_process_job` 在各阶段之间检查任务是否已被移出内存字典（用户删除或服务停机），是则中止并回收工作目录；成功 / 失败 / 取消三条路径都会回收
- **优雅停机**：lifespan 退出时终止正在运行的 ffmpeg/ffprobe 子进程（否则一个正在转码的长视频会把进程退出拖住几分钟），并清空整个上传目录
- **归属校验**：`get_job()` 同时校验 `user_id`，越权访问返回 404；该校验对管理员同样生效

### 8.5 上传安全设计

**关键前提：写在路由处理函数里的大小校验是事后检查，拦不住任何东西。**

FastAPI 会在执行路由函数**以及鉴权依赖**之前，先 `await request.form()` 把整个 multipart 解析完；Starlette 对「文件」类型的 part 不设上限，会一路写进系统临时目录。也就是说等处理函数里的 `MAX_FILE_SIZE` 判断跑起来时，字节早已落盘——实测用**无效 token** 发 300MB 请求，服务器返回 401，但 242MB 已经写进磁盘。任何人不需要有效凭据就能靠持续发大请求把服务器磁盘写满。

因此大小限制必须放在 **ASGI 中间件**层，在 body 被解析之前拦截。`UploadSizeLimitMiddleware` 的三道处理：

1. **JWT 鉴权前置**——先做一次廉价的签名与有效期校验（**不查库**），匿名或伪造请求连一个字节都传不进来；完整鉴权仍由端点依赖负责
2. **Content-Length 预检**——超限直接返回 413，一个字节都不读
3. **chunked 兜底**——没有 Content-Length 时边收边计数，超限即返回 `http.disconnect` 断开输入流，让上游的 multipart 解析立即停止

中间件的作用范围被刻意收窄：只匹配 `/api/local/upload` 一个路径，其余接口（包括原有的解析/下载）直接放行；注册在 CORS 中间件的**内层**（先 `add_middleware` 即内层），保证 CORS 仍在最外层正常工作。中间件同样识别管理员，对其放宽到 `ADMIN_MAX_FILE_SIZE`。

配套措施：

- 上限之外再留 2MB 余量给 multipart 的边界与头部开销
- 落盘按 1MB 分块写入并累计计数，作为中间件之后的第二道防线
- 落盘路径的扩展名经白名单规范化后拼接，不直接使用用户提供的文件名
- ffmpeg / ffprobe 的原始 stderr 含服务器绝对路径等内部信息，**只写服务端日志**，前端只看到固定的中文提示

### 8.6 格式校验策略

支持 **23 种容器格式**（MP4/M4V/MOV/MKV/WebM/AVI/WMV/ASF/FLV/F4V/TS/MTS/M2TS/MPG/MPEG/M2V/3GP/3G2/OGV/RM/RMVB/VOB/DIVX）。底层是 ffmpeg 解封装，这些容器本来就支持，限制只在校验层。

三层校验，职责分明：

| 层 | 依据 | 作用 |
|----|------|------|
| 扩展名 | 白名单 `ALLOWED_EXTENSIONS` | 落盘前的快速拒绝，给用户明确的「暂不支持 X 格式」提示 |
| MIME | 黑名单（text/ image/ audio/、zip/rar/7z/pdf/json/js/可执行文件） | **只用来挡明显不对的类型，不作为主要依据** |
| ffprobe | 实际探测媒体流 | **真正的把关**：确认含视频流与音轨、时长合规 |

MIME 不可靠的原因：浏览器对 MKV/FLV/TS 等格式经常给不出 MIME（空）或统一给 `application/octet-stream`，拿它做白名单会误杀大量合法视频。真正的把关交给 ffprobe——改后缀名伪装的文件（如把 zip 改成 .mp4）在探测阶段一定会被挡下，无视频流或无音轨也会直接失败并给出对应中文提示。

### 8.7 前端结果持久化

**问题**：任务状态只存在浏览器内存 + 服务端内存，刷新页面（F5）、关标签页、退出登录都会丢失 `job_id`，结果再也找不回来。

**方案**：`localStorage` 缓存（`frontend/src/api/localCache.js`），不动数据库。

- **按账号隔离**：缓存中记录 `user_id`，换账号登录读不到上一个人的内容
- **2 小时过期**：与服务端任务 TTL（`JOB_TTL_SECONDS`）对齐，避免「前端还在、后端早没了」的错位
- **只缓存文字结果**（视频元信息 / 字幕 / 总结 / 导图），**视频本身从不缓存**
- **恢复走缓存，不重新调用大模型**，因此刷新页面和重新登录都**不会重复扣配额**（实测刷新 + 退出重登后，数据库中该账号的 `daily_summary_count` 仍为 1）
- 点「删除」时同步清除缓存
- 写入超出浏览器配额（字幕过长）时退化为只存元信息，保证功能不因缓存失败而中断

**局限**：基于浏览器本地存储，换浏览器/换设备看不到。要跨设备需要做服务端历史记录（见第 9 节）。

## 9. 稳定性与容错设计

yt-dlp 类工具的核心风险是**平台接口变更导致解析大面积失效**（如 B 站风控升级返回 HTTP 412）。本模块把这类故障的恢复成本降到接近零。

### 9.1 yt-dlp 自动升级（ytdlp_manager.py）

- 后端启动时查询 PyPI 最新版本，落后则自动 `pip install --upgrade yt-dlp`
- **必须在任何 `import yt_dlp` 之前执行**（模块本身只通过 `importlib.metadata` 读版本号），升级后本进程加载的就是新版，无需二次重启
- 可通过 `YTDLP_AUTO_UPGRADE=false` 关闭（离线/锁定版本场景）
- `/api/health` 报告当前版本、最新版本、是否过期、ffmpeg 可用性，便于排查

### 9.2 友好报错（friendly_error.py）

把 yt-dlp / 网络层的英文原始报错翻译成用户可读的中文提示（412→解析引擎需升级、403→登录或地区限制、DNS 失败→检查链接与网络等），匹配不到时截断原文兜底。后端 `error` 字段只含纯提示文案，不再带「解析失败：」前缀（前缀由前端统一添加，避免重复）。

### 9.3 分享口令兼容

抖音等平台的分享口令是"文本 + 链接"混排。两道处理：

1. **路由层**：`is_douyin_url()` 先从文本中提取第一个 URL 再判断域名，口令能正确路由到抖音专用解析器
2. **yt-dlp 路径**：`/api/parse`、`/api/download`、`/api/direct-url` 统一先提取洁净 URL 再调用
3. **前端**：输入框用 `type="text"` 而非 `type="url"`——后者会被浏览器原生校验拦下（口令含中文不是合法 URL）

### 9.4 抖音风控缓解

- `DouyinParser.parse_item()` 一次请求同时满足元数据与下载需求（原先 parse+download 各请求一次，双倍风控压力）
- 在线视频 ASR 回退优先使用前端解析时已拿到的 CDN 直链，**完全不碰抖音 API**
- 直链 403/过期时自动重新解析取新鲜直链再试一次
- 已知限制：抖音公开接口对 IP 级风控敏感（短链重定向都可能被掐），高频使用需配 Cookie 或代理池（后续扩展）

针对本地视频上传解析模块，按性价比排序的下一步优化：

1. **GPU 加速**：`WHISPER_DEVICE=cuda` + `WHISPER_COMPUTE_TYPE=float16`，转写提速 5–10 倍，是体验提升最大的一项（当前 CPU 约 0.4x 实时，60 分钟视频约需 25 分钟）
2. **按内容调整模型**：中文内容改用 `WHISPER_MODEL_SIZE=small` 或 `medium`，准确率明显更好，代价是更慢
3. **排队可见性**：当前串行处理时后来者只能干等，建议在状态接口中返回队列位置与预估等待时间
4. **服务端历史记录**：建表存字幕与总结，换设备也能看，同时解除 2 小时 TTL 的限制。做之前需要重新界定「不长期保存用户数据」的边界——字幕全文要存多久
5. **多进程部署支持**：任务状态迁到 Redis。当前状态存进程内存，`--workers > 1` 时上传落到 A 进程、查状态打到 B 进程会 404，只能单进程部署
6. **说话人分离**：会议录像场景价值高，属于第一版明确不做的「高级视频理解」范畴
