# 🚀 保姆级本地运行指南

本文档手把手教你在本地跑起来 AI 万能视频下载总结器的完整前后端，**零基础也能跟着做**。



## 前置要求

| 工具 | 版本要求 | 检查命令 | 安装方式 |
|------|----------|----------|----------|
| Python | ≥ 3.10 | `python3 --version` | [官网下载](https://www.python.org/downloads/) |
| Node.js | ≥ 18 | `node -v` | [官网下载](https://nodejs.org/en)（推荐 LTS 版本） |
| npm | ≥ 9 | `npm -v` | 随 Node.js 一起安装 |
| ffmpeg | 任意 | `ffmpeg -version` | [官网下载](https://ffmpeg.org/download.html) 或 `brew install ffmpeg`（macOS） |
| ffprobe | 任意 | `ffprobe -version` | 随 ffmpeg 一起安装，无需单独装 |
| Git | 任意 | `git --version` | [官网下载](https://git-scm.com/) |

💡 关于 ffmpeg：它有两个用途，**其中一个是必需的**：

1. **在线视频下载（可选）**：合并视频和音频流（如 YouTube 高清视频的画面和声音是分开的）。不装也能跑，只是下载高清视频时会降级为低画质单一格式。
2. **本地视频上传解析（必需）**：本地视频要先用 `ffprobe` 校验（是不是真视频、有没有音轨、时长合不合规），再用 `ffmpeg` 提取音频交给语音识别。**没装 ffmpeg / ffprobe，本地视频上传功能完全用不了。**

所以现在 ffmpeg 从「强烈建议安装」升级为「**必须安装**」——只要你想用本地视频上传。安装完记得确认 `ffmpeg -version` 和 `ffprobe -version` 两条命令都能在终端里跑通（也就是加进了 PATH）。



## 第一步：获取项目代码

```bash
git clone <你的仓库地址>
cd free-video-downloader
```

💡 如果代码已经在本地，直接进入项目根目录即可。



## 第二步：获取 API Key

项目需要 **1 个必需的 API Key**，另外 1 组为可选。



### 必需：DeepSeek API Key

DeepSeek 用于 AI 视频总结功能（字幕提取后调用大模型生成总结、思维导图、问答）。

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/)，注册并登录
2. 进入「API Keys」页面，点击「创建 API Key」
3. 复制生成的 Key（以 `sk-` 开头），妥善保存

💡 新注册用户通常会赠送免费调用额度，足够学习使用。



### 可选：Stripe 支付配置

Stripe 用于 VIP 会员的在线支付功能。**本地学习时可以不配置**，不影响视频下载和 AI 总结等核心功能。

如果你想体验完整的支付流程：

1）访问 [Stripe Dashboard](https://dashboard.stripe.com/)，注册并登录

2）确保处于「测试模式」（Test mode）

3）在「开发者 → API 密钥」获取 Secret Key（以 `sk_test_` 开头）

4）在「产品」页面创建一个产品和价格，获取 Price ID（以 `price_` 开头）

5）安装 [Stripe CLI](https://docs.stripe.com/stripe-cli)，先执行 `stripe login` 登录：

然后运行以下命令启动本地 Webhook 转发：

```bash
stripe listen --forward-to localhost:8000/api/payment/webhook
```
终端会输出 Webhook Signing Secret（以 `whsec_` 开头）



## 第三步：配置环境变量

```bash
cd backend
cp .env.example .env
```

用任意文本编辑器打开 `backend/.env` 文件，填入你的配置：

```env
# ✅ 必填 - DeepSeek API Key，用于 AI 视频总结
DEEPSEEK_API_KEY=sk-你的真实key

# ✅ 必填 - JWT 密钥，用于用户登录认证
# 本地开发可以随便写一个字符串，生产环境请使用强随机值
JWT_SECRET=my-local-dev-secret-123

# 🔧 选填 - Stripe 支付配置（不配置不影响核心功能）
STRIPE_SECRET_KEY=sk_test_你的stripe密钥
STRIPE_WEBHOOK_SECRET=whsec_你的webhook密钥
STRIPE_PRICE_ID_MONTHLY=price_你的价格id

# 🔧 选填 - 前端 URL，Stripe 支付完成后跳转地址
FRONTEND_URL=http://localhost:5173

# 🔧 选填 - 本地视频上传解析（语音识别），全部不填也能直接用
# 模型大小：tiny / base / small / medium / large-v3，越大越准也越慢
WHISPER_MODEL_SIZE=base
# 设备：cpu / cuda（有 NVIDIA 显卡时用 cuda 可快 5-10 倍）
WHISPER_DEVICE=cpu
# 计算精度：cpu 用 int8，cuda 可用 float16
WHISPER_COMPUTE_TYPE=int8
# 强制识别语言，留空表示自动检测，例如 zh / en
WHISPER_LANGUAGE=
# 首次运行会自动下载模型；国内网络下载慢就打开这行镜像
# HF_ENDPOINT=https://hf-mirror.com

# 🔧 选填 - 管理员账号（逗号分隔的邮箱）
ADMIN_EMAILS=
ADMIN_MAX_FILE_SIZE_MB=5000
```

| 字段 | 必填 | 用途 |
|------|------|------|
| `DEEPSEEK_API_KEY` | ✅ 必填 | 调用 DeepSeek 大模型生成视频总结、思维导图、AI 问答 |
| `JWT_SECRET` | ✅ 必填 | 用户登录 Token 的签名密钥，本地开发可随意设置 |
| `STRIPE_SECRET_KEY` | 🔧 选填 | Stripe 支付 API 密钥，不填则支付功能不可用 |
| `STRIPE_WEBHOOK_SECRET` | 🔧 选填 | Stripe Webhook 签名验证密钥 |
| `STRIPE_PRICE_ID_MONTHLY` | 🔧 选填 | Stripe 月度会员的价格 ID |
| `FRONTEND_URL` | 🔧 选填 | 支付完成后跳转地址，默认 `http://localhost:5173` |
| `WHISPER_MODEL_SIZE` | 🔧 选填 | 语音识别模型大小，默认 `base`。可选 `tiny`/`base`/`small`/`medium`/`large-v3`，越大越准也越慢 |
| `WHISPER_DEVICE` | 🔧 选填 | 语音识别跑在哪，默认 `cpu`。有 NVIDIA 显卡填 `cuda` |
| `WHISPER_COMPUTE_TYPE` | 🔧 选填 | 计算精度，默认 `int8`（配 cpu）。用 cuda 时可改 `float16` |
| `WHISPER_LANGUAGE` | 🔧 选填 | 强制识别语言，默认留空 = 自动检测。中文视频可填 `zh` |
| `HF_ENDPOINT` | 🔧 选填 | 模型下载镜像地址。国内网络建议填 `https://hf-mirror.com` |
| `ADMIN_EMAILS` | 🔧 选填 | 管理员邮箱，逗号分隔。命中的**已注册账号**即为管理员 |
| `ADMIN_MAX_FILE_SIZE_MB` | 🔧 选填 | 管理员的上传大小上限（MB），默认 `5000` |

💡 **本地视频这几项一个都不填也能正常用**，全都有默认值。第一次跑不用管，等你觉得识别得不够准或者太慢了，再回来调 `WHISPER_MODEL_SIZE` 和 `WHISPER_DEVICE`（怎么调见后面 Q13）。

💡 **关于 `ADMIN_EMAILS`**：管理员不是新建的账号，而是贴在**已有账号**上的一个标签。填进去的邮箱必须是**已经在网站上注册过的账号**，没有单独的管理员密码，改完要重启后端才生效。管理员不受「每日 AI 总结 3 次 / 同时只能处理 1 个任务 / 500MB / 60 分钟」这些限制，但**看不了别人的数据**。详见后面 Q15。

⚠️ **注意**：`.env` 文件包含敏感信息，已被 `.gitignore` 排除，不会提交到代码仓库。



## 第四步：安装依赖

### 后端依赖（Python）

```bash
cd backend
pip install -r requirements.txt
```

💡 如果下载慢，可以切换为国内镜像：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

💡 **这一步会比你想的慢，请耐心等**：`requirements.txt` 里包含本地视频上传要用的语音识别库 `faster-whisper`（以及它依赖的 `ctranslate2`），这几个包体积比较大，装几分钟很正常。**不要以为卡住了就 Ctrl+C 中断**，中断了下次还得重来。

💡 **模型是第一次用的时候才下载的，不在这一步**：装完依赖并不会立刻下载语音识别模型。等你第一次上传本地视频时，程序才会自动去下载模型文件（默认的 `base` 模型约 140MB），下载完会缓存到本地，之后再用就不用下了。

所以「第一次上传视频时卡在『正在识别语音』很久」是正常的——它在偷偷下模型。国内网络这一步可能非常慢甚至失败，建议提前在 `backend/.env` 里配好镜像：

```env
HF_ENDPOINT=https://hf-mirror.com
```

配完重启后端再上传。具体见后面的 Q10。



### 前端依赖（Node.js）

```bash
cd ../frontend
npm install
```

💡 如果 npm install 速度慢，可以先切换为国内镜像：


### 快速体验流程（在线视频链接）

1. 注册一个账号并登录
2. 在搜索框粘贴一个视频链接（如 B 站、YouTube、抖音），点击解析
3. 系统自动解析出视频标题、封面、可选格式，选择画质后下载
4. 解析视频后查看 AI 自动生成的总结和思维导图
5. 在 AI 总结页面输入问题，体验基于视频内容的智能问答

💡 AI 总结功能需要登录，免费用户每天可使用 3 次。



### 快速体验流程（本地视频上传）

如果你手里的视频没有公开链接（本地录屏、会议录像、手机拍的素材），可以直接传上去让 AI 处理：

1. **先登录**——本地视频上传**必须登录**才能用，没登录连上传按钮都点不了
2. 在输入框上方找到来源切换，从「🔗 在线链接」切到「📁 本地上传」
3. 把视频文件**拖进去**，或者点击选择文件。支持 MP4 / MOV / MKV / AVI / WebM / FLV / WMV / TS 等 23 种常见格式
4. 等待处理。界面会依次显示「正在校验视频 → 正在提取音频 → 正在识别语音，生成字幕」，中间有百分比进度
5. 处理完成后，右侧和在线视频一样出现四个 Tab：**📝 总结摘要 / 📄 字幕文本 / 🧠 思维导图 / 💬 AI 问答**，字幕还能导出 SRT / VTT / 纯文本

💡 **默认限制**：单个文件最大 **500MB**、视频最长 **60 分钟**、同一时间只能处理 **1 个**任务。

💡 **第一次会很慢**，因为要下载语音识别模型（见 Q10）。之后 CPU 上的识别速度大约是 0.4 倍实时——也就是 10 分钟的视频大概要跑 4 分钟，60 分钟的视频要 25 分钟左右。想快就上 GPU，见 Q13。

💡 **你的视频不会被长期保存**：音频提取完就删视频，识别完就删音频，服务端只留文字结果，2 小时后自动清掉。文字结果同时缓存在浏览器里（按账号隔离、2 小时过期），所以刷新页面或退出重新登录都能恢复，而且**不会重复扣 AI 总结次数**。但换个浏览器或换台电脑就看不到了。

## 常见问题

### Q1：`ffmpeg` 未安装，下载视频报错或画质很低？

**原因**：高清视频的画面和声音是分开的，需要 ffmpeg 合并。

**解决**：
```bash
# macOS
brew install ffmpeg

# Ubuntu / Debian
sudo apt install ffmpeg

# Windows：从 https://ffmpeg.org/download.html 下载，解压后将 bin 目录加入 PATH
```

### Q2：`yt-dlp` 版本过低，解析视频失败？

**现象**：部分视频解析失败，报错 `Unable to extract`、`Unsupported URL` 或 `HTTP Error 412`。

**解决**：后端**启动时会自动检查并升级 yt-dlp 到最新版**，正常情况下重启后端（`Ctrl + C` 后重新 `python main.py`）即可自愈。如果自动升级失败（如网络问题），可手动执行：

```bash
pip install --upgrade yt-dlp
```

💡 想关闭自动升级（比如离线环境），在 `.env` 中设置 `YTDLP_AUTO_UPGRADE=false`。也可以随时访问 http://localhost:8000/api/health 查看当前 yt-dlp 版本是否过期。

### Q3：后端启动报环境变量未设置？

**原因**：`.env` 文件未创建或 Key 未填写。

**解决**：确认 `backend/.env` 文件存在，且 `DEEPSEEK_API_KEY` 已填入有效的 Key。

### Q4：端口 8000 或 5173 被占用怎么办？

**解决**：
```bash
# 查看占用端口的进程
lsof -i :8000    # macOS / Linux

# 终止占用的进程
kill -9 <PID>
```

### Q5：前端请求后端接口返回 CORS 错误？

**解决**：确保通过 `http://localhost:5173` 访问前端页面。前端会自动将 `/api` 请求通过 Vite 代理转发到后端，本项目后端也已配置了 `allow_origins=["*"]`。

### Q6：下载抖音视频失败？

**解决**：
1. 确保使用的是抖音分享链接（如 `https://v.douyin.com/xxx`）
2. 检查网络是否正常，抖音接口可能有频率限制
3. 尝试升级 yt-dlp：`pip install --upgrade yt-dlp`

### Q7：Stripe 支付功能测试不成功？

**解决**：
1. 确保 `.env` 中三个 Stripe 配置项都已填写
2. 确保 Stripe Dashboard 处于「测试模式」
3. 测试支付时使用 Stripe 提供的测试卡号：`4242 4242 4242 4242`
4. 本地测试 Webhook 需运行 Stripe CLI：
   ```bash
   stripe listen --forward-to localhost:8000/api/payment/webhook
   ```

### Q8：`pip install` 安装依赖报错？

**常见情况**：
- **bcrypt 编译失败**：安装 C 编译工具。macOS 运行 `xcode-select --install`
- **Python 版本过低**：需要 Python ≥ 3.10
- **网络超时**：使用国内镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`

### Q9：Windows 系统运行终端命令报错？

**解决**：建议在 VSCode 中把默认终端改为 Git Bash，或使用 PowerShell。避免使用 CMD。

### Q10：第一次上传本地视频，卡在「正在识别语音」半天不动？

**原因**：**大概率不是卡死，是在后台下载语音识别模型。** 模型不是随 `pip install` 一起装的，而是第一次真正用到的时候才去下载。默认的 `base` 模型约 140MB，国内网络直连可能非常慢，甚至下到一半失败。

**怎么确认**：看后端那个终端窗口。如果在下模型，通常能看到下载相关的输出；如果真的报错了，也会在这里显示。

**解决**：配国内镜像。打开 `backend/.env`，加上这一行（如果是被注释掉的，把前面的 `#` 去掉）：

```env
HF_ENDPOINT=https://hf-mirror.com
```

然后**重启后端**（`Ctrl + C` 停掉，再 `python main.py`），重新上传。

💡 模型只下载一次，之后会缓存到本地，后面再上传视频就直接开跑了。所以只有第一次这么慢，别被吓到。

### Q11：上传后提示「该视频没有音轨，无法进行语音识别」？

**原因**：这个视频文件里**只有画面、没有声音轨道**。上传后程序会先用 `ffprobe` 检查文件，发现没有音轨就直接拒绝——因为语音识别是从声音里提取文字的，没声音就没什么可识别的。

**常见情况**：无声的录屏、纯画面的素材片段、GIF 转出来的视频、某些剪辑软件导出时误关了音频轨。

**解决**：换一个有声音的视频。可以先用播放器打开确认一下能不能听到声音。

### Q12：处理完了却提示「未能从该视频中识别出任何语音内容」？

**原因**：和 Q11 不一样——这个视频**有音轨，但音轨里没有人说话**。程序跑完了整个识别流程，结果一句话都没提取出来。

**常见情况**：

- 纯音乐 / 纯背景音的视频（BGM 不算人声）
- 环境音、噪音为主，没有人声
- 人声太小、太糊，或者被背景音乐盖住了
- 说的语言太小众，模型识别不出来

**解决**：

1. 先确认视频里**确实有人说话**
2. 如果人声比较弱，试试换更大的模型：`.env` 里把 `WHISPER_MODEL_SIZE` 改成 `small` 或 `medium`，重启后端再传（代价是更慢）
3. 如果是中文视频且识别得断断续续，可以直接指定语言：`WHISPER_LANGUAGE=zh`，省掉自动检测这一步，也能减少误判

### Q13：本地视频转写太慢，怎么加速？

**先看清楚现状**：CPU 上的速度大约是 **0.4 倍实时**——60 分钟的视频要跑 25 分钟左右。这是正常的，不是出 bug 了。

**三种加速办法，按效果排序**：

**① 上 GPU（提速最明显，5-10 倍）**

有 NVIDIA 显卡的话，改 `backend/.env`：

```env
WHISPER_DEVICE=cuda
WHISPER_COMPUTE_TYPE=float16
```

重启后端生效。注意 `WHISPER_COMPUTE_TYPE` 要跟着一起改——`int8` 是给 CPU 用的，`cuda` 配 `float16` 才对。

**② 换更小的模型**

```env
WHISPER_MODEL_SIZE=tiny
```

`tiny` 比 `base` 快，但准确率会降。反过来，想要更准就往上换 `small` / `medium`，代价是更慢。中文内容用 `small` 或 `medium` 明显更准。

**③ 指定语言，省掉自动检测**

```env
WHISPER_LANGUAGE=zh
```

省下来的时间不多，但白捡的。

💡 **别指望多开几个任务来加速**：语音识别是吃 CPU 的活，后端是**串行**处理的（一次只跑一个），同时跑多个只会互相拖慢。这也是为什么有下面 Q14 那个提示。

### Q14：上传时提示「你有视频正在处理中，请等它完成后再上传新的视频」？

**原因**：这是**单用户并发上限**——同一个账号同一时间只能有 1 个视频在处理。不是出错了，就是在排队。

**为什么要限制**：语音识别是 CPU 密集型任务，同时跑多个只会让每个都变慢，还可能把机器拖垮。所以设计上就是一个一个来。

**解决**：

1. **等**——等当前那个跑完，界面上有进度百分比可以看
2. **不想等了就删掉**——在结果区点「删除」把当前任务清掉，然后就能传新的了
3. 把自己配成管理员可以绕过这个限制，见 Q15

### Q15：怎么给自己配一个管理员账号？

管理员**不是新注册一个账号**，而是给已有账号贴个标签。**没有单独的管理员密码，也不用改数据库。**

**三步搞定**：

1. **先在网站上正常注册一个账号**（比如 `you@example.com`），确认能登录
2. 打开 `backend/.env`，把这个邮箱填进 `ADMIN_EMAILS`：

   ```env
   ADMIN_EMAILS=you@example.com
   ```

   多个管理员用英文逗号隔开：

   ```env
   ADMIN_EMAILS=you@example.com,teammate@example.com
   ```

3. **重启后端**（`Ctrl + C` 然后 `python main.py`），用这个账号重新登录即可

**管理员能干什么**：不受这些限制——每日 AI 总结次数、同时处理的任务数、上传文件大小、视频时长。在线视频和本地视频两边都生效。上传区会显示「管理员账号：不受次数、并发与时长限制」。

**管理员不能干什么**：**看不了别人的数据。** 这里只是放宽你自己的用量，不是给你开后台——访问别人的任务照样 404。

💡 文件大小并不是完全无上限，管理员默认还是有个 5000MB 的兜底，防止误操作把磁盘写满。想改就调 `ADMIN_MAX_FILE_SIZE_MB`。

⚠️ 顺序别搞反了：**必须先注册账号，再填 `ADMIN_EMAILS`**。填一个还没注册过的邮箱是没用的，它不会凭空创建账号。

### Q16：Anaconda 环境下启动或上传时报 `OMP: Error #15`？

**完整报错长这样**（关键词是 `OMP: Error #15` 和 `libiomp5`）：

```
OMP: Error #15: Initializing libiomp5md.dll, but found libiomp5md.dll already initialized.
```

**原因**：Anaconda 自带的 MKL 数学库和语音识别用的 ctranslate2 各带了一份 OpenMP 运行时，同一个进程里加载两份，程序会**直接崩掉退出**。这是 Anaconda + ctranslate2 这个组合的经典问题，不是本项目的 bug。

**好消息：代码里已经处理过了。** `backend/local_video.py` 文件开头设置了环境变量 `KMP_DUPLICATE_LIB_OK=TRUE`，而且必须在语音识别库被导入**之前**执行，所以正常情况下你不会遇到这个报错。

**万一还是遇到了**（比如自己改了代码的导入顺序，或者用别的方式启动服务），手动设一下再启动：

```bash
# macOS / Linux
export KMP_DUPLICATE_LIB_OK=TRUE
python main.py

# Windows PowerShell
$env:KMP_DUPLICATE_LIB_OK = "TRUE"
python main.py
```

💡 另外提一句：装 `faster-whisper` 会把 `protobuf` 升级到较新的版本，如果你**同一个 Python 环境里还跑着 streamlit**，可能会看到依赖冲突警告。对本项目没影响，但如果那个环境里有别的项目要用，建议给本项目单独建一个虚拟环境。



## 停止项目

在各终端窗口按 `Ctrl + C` 即可停止前后端服务。

数据库文件（`backend/data/app.db`）会保留，下次启动时数据不会丢失。

⚠️ **但本地视频的任务是不保留的**：任务状态存在内存里，后端一停就全清，`backend/uploads/` 目录也会被清空。所以有视频正在处理时**别急着关后端**，等它跑完再停。

💡 已经处理完的文字结果缓存在浏览器里，重启后端再登录还能看到（2 小时内），但已经在跑一半的任务是接不回来的，只能重新上传。

⚠️ 另外，本地视频功能**不支持多进程部署**——别用 `--workers 2` 这类参数启动后端。任务状态在内存里，上传落到 A 进程、查状态打到 B 进程会直接 404。按本文档这样 `python main.py` 单进程跑没有这个问题。
